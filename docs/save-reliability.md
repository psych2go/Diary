# 保存可靠性

## 请求重试

网页为一次保存生成 UUID v4，并将 `{ text, requestId }` 保存在浏览器的
`diary-pending-save` 中。未确认成功时，原文重试复用相同 ID；更改正文视为新的保存。
请求等待 20 秒后提示结果未确认，不自动重试。超时不代表服务器未写入。

服务端将 ID、正文规范化后的 SHA-256 和首次保存时间，以独立 HTML 注释行写入
同一个 Markdown 文件。正文和去重标记通过一次原子替换写入，不使用独立数据库。
历史读取 API 隐藏标记，直接打开 Markdown 源文件仍可看到它。不要删除这些标记，
否则相应请求无法去重。旧文件不会被批量修改，未携带 ID 的旧客户端仍可保存，
但不享有去重保障。同一 ID 配不同正文会返回 400。

重试返回首次保存的日期和时间；跨日或进程重启后也能识别已完成的保存。
当前实现每次带 ID 的保存会扫描有效日记文件，适合个人日记规模；大量数据时需要
可重建索引来减少读取。写入队列以数据根目录为单位，**只支持单进程写入**，
不要让多个实例同时写同一个目录。

## 本机草稿

浏览器存储失败时降级到当前页面内存，显示“草稿仅保留在当前页面”的警告。
用户仍可提交到服务器，但关闭页面将丢失无法持久化的草稿和重试 ID。
草稿和待确认保存内容仍是浏览器中的明文，不是加密存储。
页面提供“本机草稿管理”：按日期列出草稿，用户主动选择恢复；切换前保留当前草稿，
不会自动用旧内容覆盖编辑区。恢复的旧草稿仍按服务器实际保存时间记入日记，
而不是回填到草稿日期。编辑期间固定草稿存储键，避免跨午夜产生重复残留；成功保存后
下一份草稿使用当前日期。

“清除全部本机草稿”需要确认，仅删除本站日记草稿和待确认保存信息，不删除服务器
日记、登录状态或无关的浏览器存储项。如果无法确认本机清理成功，页面会提示使用
浏览器设置清除此站点数据。保存请求进行中不能切换或清理草稿。

退出会清除当前编辑草稿和待确认保存信息，但其它日期草稿仍会保留。
清除浏览器数据、退出后重新提交或修改正文，
不属于原请求重试，不能保证去重。

## 写入持久性

临时文件使用随机文件名、独占创建和 0600 权限；写入后同步文件，再 rename 替换，
随后同步所在目录。年份目录的创建也会同步到数据根目录。
运行中失败会尝试清理临时文件；强制终止或断电仍可能留下临时文件，但列表不会收录它们。
依赖支持目录 fsync 的文件系统（部署目标为 Linux）；不把持久化失败误报为成功。
这不是备份，也不能保证硬件故障时数据一定存活。

## 验证

运行 `npm test`。测试覆盖原文重试、并发重试、跨日重试、独立模块状态去重、
ID 冲突、文件权限、rename 失败清理、HTTP 接口去重及草稿存储故障。
此外覆盖旧草稿恢复、清理确认及存储键隔离、统计响应乱序、异步密码校验并发限制。
这些是逻辑回归测试，不是实际断电或硬件故障测试。

## 登录与界面请求

服务器登录使用异步 scrypt，最多同时运行两次密码校验，超过限制立即返回 503 和
`Retry-After: 1`，不建立无界等待队列。原有按客户端的失败登录限流继续生效。
生成密码哈希的离线工具仍可使用同步实现。

登录、会话和历史请求默认等待 10 秒，保存请求等待 20 秒。前端阻止重复登录提交，
过时的登录或统计结果不得覆盖当前会话和界面状态。
